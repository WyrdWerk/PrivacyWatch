# PrivacyWatch structured fields (v2)

**Goal:** make `providers.json` queryable and evidence-backed so it can serve an
API, briefs and cross-market analysis without breaking the live site.

**Constraint:** keep it simple. One file (`providers.json`), no new tooling, no
new dependencies. Everything is additive: existing `label`/`detail` text stays and
`index.html` works unchanged.

## Fields

Implemented in `scripts/lib/v2-fields.mjs` (the source of truth for the
vocabularies), mirrored in `providers.schema.json`, checked by `npm run validate`.

| Field | Values |
|---|---|
| `training.default` | `off` · `on` · `opt-in` · `tier-dependent` · `silent` · `conflicting` |
| `training.optOut` | `setting` · `api-param` · `email` · `contract` · `not-needed` · `none` · `silent` |
| `retention.kind` | `none` · `transient` · `fixed` · `until-deleted` · `indefinite` · `silent` |
| `retention.days` | integer, only when `kind` is `fixed` |
| `zdr.access` | `default` · `self-serve` · `approval` · `enterprise` · `none` · `silent` |
| `location.regions` | ISO 3166-1 alpha-2 codes, `EU`, or `GLOBAL`; `[]` = silent |
| `compliance.dpa` | `public` · `on-request` · `enterprise` · `none` · `silent` |
| `compliance.soc2` | `type1` · `type2` · `none` · `silent` |
| `compliance.hipaaBaa` | `available` · `enterprise` · `none` · `silent` |
| `incidents[]` | `{ date: YYYY-MM, type: breach·regulatory·ban·allegation, confirmed, summary, sourceUrl }` |
| `evidence[]` | `{ field, url, quote, retrieved: YYYY-MM-DD }` |

`field` in an evidence entry is one of `training`, `retention`, `zdr`,
`location`, `compliance`, `incidents`.

## Rules

1. **Silent is not unknown.** `silent` = we read the document and it doesn't
   say. A missing field = not researched yet.
2. **Structured values need evidence.** Any group with a structured value needs
   at least one `evidence` entry for that field, with a verbatim `quote` unless
   the value is `silent`.
3. **Tiers stay in prose.** When free/paid/enterprise differ, use
   `tier-dependent` and explain in `detail`. No per-plan data model.
4. **Incident flag is derived.** When `incidents` is present, `incident` must be
   true exactly when a confirmed, non-`allegation` entry exists.
   `incidentDetail` stays for the site.
5. `sourceDate` remains the row's last-verified date.

## Rollout

1. ✅ Validator, tests, schema (this change).
2. Pilot: US Frontier (8 rows), researched against live primary sources.
3. Remaining cohorts in batches: Chinese → Coding → major inference hosts → long
   tail. The rows last verified May–June get re-verified along the way. One PR and
   one CHANGELOG entry per batch.
4. Then: read-only API over the structured fields, then briefs.

`npm run validate` prints coverage (`structured: N/97 rows complete`) so
progress is visible without extra tooling.
